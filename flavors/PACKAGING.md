# Flavor Packaging Guide

This document describes how to package, install, and distribute Arroolio
flavors as standalone Ruby gems. The arrolio gem itself is **100%
flavor-agnostic** — it contains no flavor-specific Ruby, YAML, XSL, or
fixture data. Every flavor lives in its own directory and its own gem.

## The flavor encapsulation invariant

> A flavor is XSL + 3 generated YAML files. ZERO Ruby code.

The arrolio gem's `lib/` contains no flavor-named files (`oiml`, `iso`,
`iec`, `bsi`, …). The gemspec excludes `flavors/`. The gem's own specs
use a synthetic sample fixture (`spec/fixtures/flavors/sample/`) — they
do not depend on any real flavor.

## Anatomy of a flavor gem

```
my-flavor/
  my_flavor.gemspec
  lib/
    my_flavor.rb                     # optional: registers with Arroolio::Flavor::Registry
  flavors/
    my_flavor/
      manifest.yml                   # TODO 54: declares name, version, XSL, fonts
      layout_spec.yml                # generated by xsl_to_config.rb
      adapter_rules.yml              # generated by xsl_to_config.rb
      flow_rules.yml                 # generated by xsl_to_config.rb
      upstream.xsl                   # authoritative reference
  spec/
    end_to_end_spec.rb               # renders a fixture via the pipeline
    fixtures/
      *.xml                          # sample input documents
```

## Creating a new flavor

1. **Acquire the XSL**: place it at `flavors/<name>/upstream.xsl`.
2. **Generate the config**:
   ```bash
   cd /path/to/arrolio
   bundle exec rake flavor:generate XSL=/path/to/flavors/<name>/upstream.xsl OUT=/path/to/flavors/<name>
   ```
   This runs `scripts/xsl_to_config.rb` and writes
   `layout_spec.yml`, `adapter_rules.yml`, `flow_rules.yml`.
3. **Customize the selectors** (if your vocabulary isn't Metanorma
   standoc): edit `adapter_rules.yml`'s `selectors:` block to declare
   every XML element name the flavor uses.
4. **Customize the styles** (if the generator's defaults are wrong):
   edit `layout_spec.yml` to match your XSL's visual intent.
5. **Customize the flow** (if your page-sequence structure differs):
   edit `flow_rules.yml`'s `page_sequences:` and `cover_content:`.
6. **Render a fixture**:
   ```bash
   bundle exec ruby exe/arrolio2pdf input.xml output.pdf /path/to/flavors/<name>
   ```
   Or programmatically:
   ```ruby
   Arroolio::ConfigDrivenPipeline.render(xml, io: io, flavor_dir: '/path/to/flavors/<name>')
   ```

## The selector contract

The generic adapter (`Arroolio::GenericAdapter`) reads every XML
element and attribute name from `adapter_rules.yml`'s `selectors:`
block. The adapter has ZERO hardcoded element names outside a clearly
labelled `DEFAULT_SELECTORS` fallback (which documents the Metanorma
standoc convention).

Required selector keys (with standoc defaults shown):

```yaml
selectors:
  heading: fmt-title
  heading_depth_attribute: depth
  list_item: li
  list_item_label: fmt-name
  paragraph: p
  term_number: fmt-name
  term_preferred: fmt-preferred
  term_definition: fmt-definition
  term_source: fmt-termsource
  note_label: fmt-name
  figure_image: image
  figure_caption: fmt-name
  figure_caption_fallback: name
  table_row: tr
  table_cell: [td, th]
  table_header: thead
  table_body: tbody
  biblio_tag: biblio-tag
  biblio_formattedref: formattedref
  image_src_attribute: src
  image_alt_attribute: alt
  id_attribute: id
  autonum_class: fmt-autonum-delim
  stem: stem
  stem_formatted: fmt-stem
  math: math
  preface_container: preface
  preface_children: [clause, foreword]
  bibliography_container: bibliography
  bibliography_reference: references
  bibliography_item: bibitem
  fallback_title: title
  span: span
  tab_inline: tab
  break_inline: br
```

A flavor with a different vocabulary overrides these. The OCP guard
spec (`spec/arrolio/ocp_grep_spec.rb`) verifies a non-Metanorma
vocabulary parses correctly through the generic adapter.

## The layout_spec contract

`layout_spec.yml` describes the visual intent of the flavor. Required
blocks:

- `default_page_template`: the page template name to use by default.
- `page_templates`: page sizes, margins, region extents.
- `styles`: every style the flow builder references (body, heading_1
  through heading_6, list_bullet, table_cell, cover_*, etc.).
- `flows`: region→style mappings.
- `header_footer` (optional): margin_top/margin_bottom/margin_lr,
  header_offset/footer_offset, font_name, font_size, rule_width.
  Falls back to engine-safe defaults if absent.
- `cover_logo` (optional): width_mm, aspect_ratio, margin_mm.
- `font_paths` (optional): maps font family names to TTF paths.

## The flow_rules contract

`flow_rules.yml` describes how to build flowables from a
`Content::Document`. Required blocks:

- `page_sequences`: array of `{ role, header, footer, build_content? }`
  entries. Roles are arbitrary symbols (no hardcoded meaning in core
  beyond `:cover` skipping the header/footer in the renderer).
- `cover_content` (when `build_content: cover_content`): array of
  `{ type: spacer|text, source, style, when? }` entries.
- `section`: heading/body style resolution and page-break rules.
- `content_to_flowable`: maps Content class names to flowable types.
- `toc` (optional): `{ styles: { entry, sub }, top_offset }`.

## Registering a flavor (optional)

A flavor gem may register itself with the `Flavor::Registry` at load
time so applications can look it up by name:

```ruby
# lib/my_flavor.rb
require 'arrolio'

class MyFlavor
  def self.render(xml, io:, **opts)
    flavor_dir = File.expand_path('../flavors/my_flavor', __dir__)
    Arroolio::ConfigDrivenPipeline.render(xml, io: io, flavor_dir: flavor_dir, **opts)
  end
end

Arroolio::Flavor::Registry.register(:my_flavor, MyFlavor)
```

Applications then render via:

```ruby
require 'my_flavor'  # loads the gem, triggers registration
Arroolio::Flavor::Registry.for(:my_flavor).render(xml, io: io)
```

## Verification checklist

A flavor is correctly encapsulated when:

- [ ] No Ruby files under the flavor directory
- [ ] `layout_spec.yml`, `adapter_rules.yml`, `flow_rules.yml` are
      generated (or derived) from the upstream XSL
- [ ] A real fixture renders via the generic pipeline
- [ ] The flavor does NOT modify any file under arrolio's `lib/`
- [ ] The flavor is distributed as its own gem (`arrolio-<name>`)
- [ ] The flavor's specs run independently of arrolio's specs

## Why this matters

Without strict encapsulation, every flavor is a fork of arrolio. With
it, arrolio is a stable engine that any number of flavor gems can plug
into — adding a new flavor never requires touching the engine, and
upgrading the engine never breaks existing flavors (as long as the
selector/layout_spec/flow_rules contracts are honored).
